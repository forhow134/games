# 05-forest-quest / DESIGN.md

## 1. 游戏概述

**Forest Quest（森林大冒险）** 是一款基于 Three.js 的 3D 第三人称卡通平台跳跃游戏。玩家扮演一只机智勇敢的小狐狸，穿越神秘的魔法森林与幽暗岩洞，在 6 个风格迥异的关卡中奔跑、跳跃、收集水晶、击退敌人，最终击败守护森林的远古石巨人，解开森林深处的秘密。

游戏采用暖色调卡通 low-poly 美术风格，场景从阳光明媚的森林入口逐渐过渡到阴暗神秘的岩洞深处，通过光照和色调变化营造氛围递进。所有角色与场景元素均为低多边形建模，配合柔和的边缘光与阴影，呈现轻松明快又不失冒险感的视觉体验。

### 操作方式

| 按键 | 功能 |
|------|------|
| `W / A / S / D` | 角色前后左右移动 |
| `Space` | 跳跃（支持二段跳，L4 起可用） |
| `Shift` | 按住奔跑（移动速度 × 1.6） |
| `E` | 互动/确认（触发机关、进入传送门） |
| `鼠标拖拽` | 旋转摄像机视角（第三人称跟随） |
| `鼠标滚轮` | 调整摄像机远近（距离范围 6-16） |
| `Esc` | 暂停游戏 / 关闭弹窗 |

操作手感追求"轻盈但可控"：跳跃带有轻微的滞空感，落地有缓冲；奔跑时摄像机 FOV 轻微外扩（+3°），增强速度感。

> **决议补充(2026-05-03)**：二段跳从开局即可用，不再作为 L4 解锁机制。操作方式表中"L4 起可用"标注作废，但保留 Space 键功能描述。详见末尾"设计决议"第 2 条。

## 2. 核心循环

```
开始界面 → 关卡选择 → 加载关卡 → 游戏进行 → 结算
                ↑___________________________↓
```

**单局循环：**

1. **探索移动** — 玩家通过 WASD 在 3D 平台间移动，利用跳跃跨越间隙
2. **收集水晶** — 每关散布 10 颗水晶，收集数量决定星级评价
3. **应对敌人** — 蘑菇怪巡逻、小精灵追击、石傀儡冲撞，可通过跳跃踩踏或躲避
4. **到达终点** — 触碰关卡终点传送门（L6 需击败 Boss 后传送门才激活）
5. **星级结算** — 根据水晶收集数评定 1-3 星，解锁下一关
6. **进度存档** — localStorage 自动记录每关最高星数和解锁状态

**失败重试：** 掉出关卡边界或受到 3 次伤害 → 弹出失败界面 → 点击重试从本关起点重新开始，水晶和敌人状态重置。

## 3. 六关结构总览

| 关卡 | 名称 | 一句话概括 | 独有机制 |
|------|------|-----------|---------|
| L1 | 森林入口 | 教学关，熟悉移动与跳跃 | 静态平台、无敌人、3 颗水晶可见 |
| L2 | 森林深处 | 引入动态平台与基础敌人 | 水平移动平台 + 垂直升降平台、蘑菇怪巡逻 |
| L3 | 峡谷 | 考验精准跳跃与时机把控 | 密集尖刺陷阱 + 火焰喷射器、小精灵首次出现 |
| L4 | 岩洞入口 | 垂直向上探索 | 弹跳平台（踩下弹射）、二段跳解锁 |
| L5 | 岩洞深处 | 新敌人 + 复杂地形 | 石傀儡冲撞、移动平台与陷阱组合 |
| L6 | Boss 岩室 | 终极挑战 | 石巨人 2 阶段 Boss 战、击败后激活通关传送门 |

**关卡解锁规则：** 完成前一关即可解锁下一关，不要求特定星级。但全 3 星通关会在关卡选择界面展示特殊徽章。

**跨关复用策略：** 6 关尽量复用同一批模型，通过以下方式做关卡区分：
- **L1-L3（森林区）：** 大量树木、蘑菇装饰、木质平台、暖绿色调光照
- **L4-L6（岩洞区）：** 岩石、钟乳石、石质平台、冷蓝/橙色调光照、火把点光源
- **敌人出现密度递增：** L2 出现蘑菇怪，L3 加入小精灵，L5 加入石傀儡，L6 仅 Boss
- **平台类型逐步解锁：** 静态 → 水平移动 → 垂直升降 → 弹跳 → 组合

- 终点前一个小间隙跳跃作为最终教学检验
- 无敌人、无陷阱、无掉落死亡（下方有隐形兜底平台，掉落后传送回最近安全点）

- 水晶分布在移动平台上，需要把握时机跳跃收集

- 部分水晶放置在陷阱边缘，高风险高回报

- 岩洞顶部有发光水晶簇装饰，终点传送门在最高处
- 部分平台边缘有小型钟乳石装饰，纯视觉无碰撞

- 移动平台 + 弹跳平台 + 陷阱的三重组合考验综合操作
- 岩洞深处光照昏暗，仅有火把点光源照亮局部区域，增加紧张感
- 隐藏区域：引导石傀儡撞碎石墙后，内部有 2 颗额外水晶（但总分仍按 10 颗计算，溢出不计入星级）

- 无水晶收集，Boss 战本身即为挑战

## 5. 物理参数

以下参数为建议值，后续代码实现时可直接引用。所有单位基于 Three.js 世界坐标系（1 单位 ≈ 1 米）。

| 参数 | 建议值 | 说明 |
|------|--------|------|
| 重力加速度 `g` | `25.0` | 比现实重力略大，增强平台跳跃的紧实感 |
| 跳跃初速度 `v0` | `10.0` | 配合 g=25，最大跳跃高度约 2.0m |
| 二段跳初速度 | `8.5` | 略低于首跳，防止过度浮空 |
| 横向移动速度 `walkSpeed` | `5.0` | 普通行走 |
| 奔跑倍率 `runMult` | `1.6` | 奔跑速度 = 8.0 |
| 空中横向控制系数 `airControl` | `0.6` | 空中仍可微调方向，但弱于地面 |
| 最大下落速度 `maxFallSpeed` | `20.0` | 防止过深坠落时速度失控 |
| 地面摩擦力 `groundFriction` | `12.0` | 松手后迅速减速，避免"溜冰" |
| 转向速度 `turnSpeed` | `12.0` | 角色模型朝向平滑转向，单位：弧度/秒 |
| 角色碰撞体 | `0.4m × 0.8m × 0.4m` | AABB，宽×高×深，底部中心为原点 |
| 平台碰撞厚度 | `0.2m` | 平台顶部碰撞面厚度，用于 Raycaster 地面检测 |
| 摄像机距离 `camDist` | `10.0` | 默认第三人称距离 |
| 摄像机高度偏移 `camHeight` | `3.5` | 相对角色头部的垂直偏移 |
| 摄像机平滑 lerp 系数 `camLerp` | `0.12` | 每帧插值系数，较低值 = 更平滑跟随 |
| 摄像机 FOV 基础值 | `60°` | 奔跑时动态外扩至 `63°` |
| 掉落死亡边界 `fallBound` | `-15.0` | Y 坐标低于此值判定死亡 |

**地面检测：** 使用 Raycaster 从角色底部中心向下发射射线（长度 0.3m），命中平台碰撞体即判定为"着地"。着地后重置跳跃次数、刷新二段跳可用状态。

**碰撞系统：** 手写 AABB（轴对齐包围盒）碰撞检测，适用于角色-平台、角色-敌人、角色-收集品。敌人与陷阱之间不做碰撞处理。

> **决议补充(2026-05-03)**：二段跳上升速度统一为 `v1 = 8.0`（替代原表中 `8.5`），从开局生效。摄像机仅提供默认自动跟随一种模式，`camLerp = 0.12` 为固定值，不做手动/自动切换。详见末尾"设计决议"第 2、3 条。

## 6. 敌人行为

### 6.1 蘑菇怪（Mushroom）

| 属性 | 数值 |
|------|------|
| 出现关卡 | L2-L5 |
| 巡逻范围 | 固定平台两端，半径 3-5m |
| 巡逻速度 | `1.5` m/s |
| 伤害方式 | 触碰扣 1 血，短暂无敌帧 1.5s |
| 击败方式 | 跳跃踩踏头顶（类似经典平台跳跃） |
| 模型 | `enemy-mushroom.glb` |

**行为逻辑：** 在出生点为中心的平台范围内左右巡逻，到达边界后转身。无追击逻辑，纯地形障碍。被踩踏后播放压扁动画并消失，掉落 1 颗小金币（纯视觉加分，不影响星级）。

### 6.2 小精灵（Sprite）

| 属性 | 数值 |
|------|------|
| 出现关卡 | L3-L5 |
| 飞行高度 | 平台上方 `1.5-2.5m` 随机 |
| 巡逻路径 | 固定曲线路径（正弦波或圆形） |
| 巡逻速度 | `2.0` m/s |
| 追击触发范围 | 水平距离 `4.0m` 内 |
| 追击速度 | `4.5` m/s |
| 伤害方式 | 触碰扣 1 血 |
| 模型 | `enemy-sprite.glb` |

**行为逻辑：** 平时沿固定路径飞行，玩家进入追击范围后转向直冲玩家，持续 3 秒或直到碰撞/玩家脱离范围。碰撞后小精灵反弹回原路径。无法被踩踏，只能躲避。

### 6.3 石傀儡（Small Golem）

| 属性 | 数值 |
|------|------|
| 出现关卡 | L5 |
| 巡逻范围 | 固定区域，半径 4m |
| 巡逻速度 | `1.0` m/s |
| 冲撞触发范围 | 水平距离 `5.0m` 内 |
| 冲撞速度 | `8.0` m/s |
| 冲撞冷却 | `4.0` 秒 |
| 伤害方式 | 冲撞触碰扣 1 血并击退 |
| 特殊能力 | 冲撞可破坏脆弱石墙 |
| 模型 | `enemy-golem-small.glb` |

**行为逻辑：** 平时缓慢巡逻，发现玩家后停止 0.5s 蓄力，然后沿直线高速冲撞，直到撞墙或超出最大距离 10m。冲撞结束后进入 4s 冷却，期间原地摇晃恢复。冲撞路径上有脆弱石墙时，石墙破碎并播放碎石粒子效果。

> **决议补充(2026-05-03)**：石傀儡撞碎脆弱石墙后掉落 bonus crystal（最多 2 颗），不计入每关固定 10 颗总数，仅作额外收集展示。详见末尾"设计决议"第 6 条。

### 6.4 石巨人 Boss（Stone Giant）

| 属性 | 数值 |
|------|------|
| 出现关卡 | L6 |
| 总血量 | `8` 点（踩踏 8 次） |
| 模型尺寸 | 高约 `4.5m` |
| 模型 | `boss-stone-giant.glb` |

**阶段 1 — 地面追击（血量 8 → 4）：**
- 移动速度：`3.5` m/s，始终朝向玩家移动
- 攻击方式：靠近玩家后抬脚踩踏（范围 2m，预判 0.8s），踩中扣 1 血并震屏
- 弱点：头顶有发光水晶，玩家跳跃踩踏头顶扣 Boss 1 血
- 受击后 Boss 后仰 0.5s，无敌

**阶段 2 — 狂暴召唤（血量 4 → 0）：**
- 触发条件：血量降至 4
- 行为变化：停止移动，固定在场地中央
- 攻击方式 1：召唤落石（每 2s 从顶部随机位置掉落 1 块，落点有红圈预警 1s）
- 攻击方式 2：地面冲击波（每 4s 以 Boss 为中心释放环形冲击波，玩家需跳跃躲避）
- 弱点：头顶水晶依然可踩，但 Boss 会随机挥手干扰，需要把握时机

**死亡演出：** 血量归零后，Boss 身体出现裂纹发光，播放 3s 碎裂动画，化为碎石堆。随后场地中央升起通关传送门（`portal-finish.glb`），旋转发光。

> **决议补充(2026-05-03)**：L6 Boss 战保持纯 1v1，不加入小怪波次。Boss 阶段切换逻辑无需扩展“召唤小怪”分支。详见末尾“设计决议”第 1 条。

## 7. 收集系统

### 水晶（Crystal）

- 每关固定放置 **10 颗水晶**
- 水晶悬浮于空中，缓慢自转 + 上下浮动（振幅 0.2m，周期 2s）
- 收集时播放清脆音效 + 粒子爆裂效果
- 模型：`crystal.glb`

### 星级评分

| 收集水晶数 | 星级 | 解锁条件 |
|-----------|------|---------|
| 4-6 颗 | ⭐ | 无 |
| 7-9 颗 | ⭐⭐ | 无 |
| 10 颗 | ⭐⭐⭐ | 无 |

星级仅影响关卡选择界面的展示和玩家成就感，不阻塞关卡解锁。

### 计时系统

- 每关记录通关用时，仅用于个人挑战，不影响星级
- 关卡选择界面显示每关最快通关时间

### localStorage 存档结构

```json
{
  "version": 1,
  "levels": {
    "1": { "unlocked": true,  "stars": 2, "bestTime": 45.3, "crystals": 7 },
    "2": { "unlocked": true,  "stars": 3, "bestTime": 62.1, "crystals": 10 },
    "3": { "unlocked": true,  "stars": 1, "bestTime": 88.5, "crystals": 5 },
    "4": { "unlocked": true,  "stars": 0, "bestTime": null, "crystals": 0 },
    "5": { "unlocked": false, "stars": 0, "bestTime": null, "crystals": 0 },
    "6": { "unlocked": false, "stars": 0, "bestTime": null, "crystals": 0 }
  },
  "settings": {
    "locale": "zh",
    "sound": true,
    "music": true
  }
}
```

**存档键名：** `forest_quest_save`

**存档规则：**
- 首次进入游戏自动初始化
- 关卡完成时自动保存（取最高星级和最快时间）
- 设置变更时即时保存
- 不提供手动存档/读档功能

> **决议补充(2026-05-03)**：L5 石傀儡撞墙掉落的 crystal 为 bonus（最多 +2 颗），不计入 10 颗总数。星级评分仍按 10 颗主收集计算；bonus 数可单独存入存档字段，不影响原有 `crystals` 统计。详见末尾"设计决议"第 6 条。

## 9. 胜负条件与失败处理

### 胜利条件

| 关卡 | 胜利条件 |
|------|---------|
| L1-L5 | 角色触碰终点传送门碰撞体 |
| L6 | 击败石巨人 Boss，随后触碰激活的通关传送门 |

### 失败条件

| 条件 | 处理方式 |
|------|---------|
| 生命耗尽（受到 3 次伤害） | 弹出失败界面，可选择重试或返回选关 |
| 掉出关卡边界（Y < -15） | 直接判定失败，弹出失败界面 |

### 伤害与无敌机制

- 玩家初始 3 颗心（3 HP）
- 受到敌人/陷阱伤害时：
  1. 扣 1 HP
  2. 触发 1.5s 无敌时间（角色半透明闪烁）
  3. 受到击退效果（与伤害来源方向相反，速度 5m/s，持续 0.3s）
  4. 摄像机轻微震动（强度 0.3，持续 0.2s）
- 无敌期间不再受到伤害
- 掉出边界不触发无敌，直接死亡

### 检查点机制

- L1-L5：无中间检查点，死亡后从关卡起点重新开始
- L6 Boss 战：阶段 1 → 阶段 2 切换时自动记录检查点，若死亡可从阶段 2 开始（Boss 血量恢复至 4）

## 设计决议(2026-05-03 用户确认)

### 1. L6 Boss 战不加小怪波次

**决议内容：** L6 石巨人 Boss 战保持纯 1v1 单挑，不加入任何小怪波次干扰。Boss 本身的两阶段机制已足够构成终极挑战。

**影响范围：** `6. 敌人行为` / `L6 Boss 岩室` ASCII 地图 / 胜负条件。

**实施提示：** 代码实现时 `Level6` 的敌人数组只放 Boss 一个实体；Boss 阶段切换逻辑保持现状，无需扩展"召唤小怪"分支。L6 ASCII 地图中不标注小怪出生点。

### 2. 二段跳开局就有

**决议内容：** 二段跳能力从游戏开始即可用，不再作为 L4 的解锁机制。前期难度通过关卡地形设计（平台间距、陷阱密度）来控制，而非限制玩家能力。

**影响范围：** `5. 物理参数`（需新增"二段跳上升速度 v1=8"）/ `1. 游戏概述` 操作方式段 / `3. 六关结构总览` L4 描述 / `4. 每关 ASCII 地图` L4 说明。

**实施提示：** 在 `constants.js` 中定义 `MAX_JUMPS = 2` 作为全局常量；角色初始化时即具备二段跳，不再依赖关卡进度标记。L4 的"解锁"文案改为"首次需要连续使用二段跳的关卡"。

### 3. 摄像机只做默认自动跟随

**决议内容：** 摄像机仅提供一种默认自动跟随模式（角色后方固定角度，平滑插值），不实现手动切换功能。鼠标拖拽旋转和滚轮缩放保留，但"自动跟随"不作为可选项存在——它就是唯一行为。

**影响范围：** `5. 物理参数`（摄像机平滑系数段）/ `1. 游戏概述` 操作方式段。

**实施提示：** `CameraController` 类只实现一种 follow 模式，无需维护 `mode` 状态机。平滑系数 `camLerp = 0.12` 作为固定值，不提供玩家可调选项。

### 4. 不做移动端虚拟摇杆

**决议内容：** 本作仅支持 PC 端（键盘 + 鼠标），不开发移动端虚拟摇杆和触控按钮适配。输入系统只监听键盘事件和鼠标事件。

**影响范围：** `10. 技术栈声明` / `1. 游戏概述` 操作方式段 / 性能目标中的移动端帧率可移除。

**实施提示：** 代码中不引入任何 touch 事件监听；`InputManager` 只处理 `KeyboardEvent` 和 `MouseEvent`。README 和 index.html 的 viewport 设置保持桌面优先。

### 5. BGM/音效清单延后

**决议内容：** Phase 1 不产出具体音轨或音效文件，只在代码中预留事件钩子名称清单。具体音频资源在 Phase 4-5（美术与音频整合阶段）再补充。

**影响范围：** 全局音频系统架构 / `src/constants.js` 中的事件名定义。

**实施提示：** 在 `constants.js` 或 `audio/AudioManager.js` 中定义以下钩子常量，实现时留空或打印 log：
- `onJump` — 角色起跳
- `onCollect` — 收集水晶
- `onHurt` — 受伤
- `onBossEnter` — Boss 战开始
- `onLevelComplete` — 关卡完成
后续接入实际音频时只需替换对应 hook 的实现，无需改动调用方。

### 6. L5 石傀儡撞墙掉水晶作为 bonus，最多 +2 颗，不计入 10 颗总数

**决议内容：** L5 石傀儡冲撞破坏脆弱石墙后，掉落的水晶属于 bonus crystal（最多 2 颗），不计入每关固定的 10 颗水晶总数。星级评分仍只按 10 颗计算，bonus 作为额外收集展示在结算界面的"额外发现"栏。

**影响范围：** `7. 收集系统`（需新增 bonus crystal 规则）/ `6. 敌人行为` 石傀儡段 / `8. UI 布局草稿` 关卡胜利弹层 / `3. 六关结构总览` L5 描述。

**实施提示：**
- `Level5` 的水晶数组分为 `crystals: 10`（主收集）和 `bonusCrystals: 2`（隐藏）。
- 石傀儡冲撞逻辑中，撞墙后检测该墙是否为 `fragileWall` 类型，若是则实例化 bonus 水晶并播放碎石粒子。
- 结算时星级只读主收集数；bonus 数单独显示在弹层底部"额外发现：X/2"。
- localStorage 存档结构可为 `bonusCrystals` 新增字段，不影响原有 `crystals` 统计。

### 7. 关卡选择缩略图使用预截图

**决议内容：** 关卡选择界面的 6 张缩略图不在运行时实时渲染，而是在 Phase 5（美术素材整合阶段）手动截取 6 张静态场景预览图，放入 `public/thumbnails/` 目录作为贴图资源。

**影响范围：** `8. UI 布局草稿` 关卡选择界面段 / 项目文件结构（预期）/ 构建流程。

**实施提示：**
- `LevelSelectScreen` 直接使用 `<img src="/thumbnails/level-N.png">` 加载预截图，不创建额外的 Three.js 渲染器或场景。
- `public/thumbnails/` 目录在 Phase 5 前可先用占位图（纯色 + 关卡编号）代替。
- 截图规格建议：512×512 PNG，视角统一为关卡起点处默认摄像机角度，保持视觉一致性。
